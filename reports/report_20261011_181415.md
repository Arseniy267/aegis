### 3. Векторы атаки

1. **FTP (vsftpd 2.3.4)**
   - **CVE-2011-2523**: Логин с ':)' открывает root shell на порту 6200. Эксплуатация этого CVE позволяет получить полный доступ к системе.

2. **SSH (OpenSSH 4.7p1)**
   - **CVE-2016-0777**: Утечка приватного ключа (только клиент). Эксплуатация этого CVE позволяет получить доступ к системе без пароля.
   - **CVE-2018-15473**: Утечка приватного ключа через malformed auth request. Эксплуатация этого CVE также позволяет получить доступ к системе без пароля.

3. **Telnet**
   - **CVE-2022-39028**: NULL pointer dereference. Эксплуатация этого CVE может привести к удаленному коду выполнения.
   - **CVE-2021-27171**: Возможность запуска telnetd как root на порту 26/tcp. Эксплуатация этого CVE позволяет получить полный доступ к системе.

4. **SMTP (Postfix smtpd)**
   - **CVE-2024-27305**: SMTP smuggling. Эксплуатация этого CVE может привести к утечке данных и взлому системы.
   - **CVE-2023-51764**: SMTP smuggling. Эксплуатация этого CVE также может привести к утечке данных и взлому системы.

5. **DNS (ISC BIND 9.4.2)**
   - **CVE-2008-0122**: Off-by-one в inet_network(), DoS. Эксплуатация этого CVE может привести к отказу в обслуживании.

6. **HTTP (Apache httpd 2.2.8)**
   - **CVE-2017-7659**: DoS через malformed HTTP/2 request. Эксплуатация этого CVE может привести к отказу в обслуживании.

7. **Samba (smbd 3.X - 4.X)**
   - **CVE-2010-4221**: Stack overflow в mod_tls (pre-auth RCE). Эксплуатация этого CVE позволяет получить полный доступ к системе.

8. **MySQL (MySQL 5.0.51a)**
   - **CVE-2012-2122**: Обход аутентификации через повторные попытки. Эксплуатация этого CVE позволяет получить доступ к системе без пароля.

9. **PostgreSQL (PostgreSQL DB 8.3.0 - 8.3.7)**
   - **CVE-2013-1900**: Утечка памяти через неверный random number generator. Эксплуатация этого CVE может привести к утечке данных.

10. **VNC (protocol 3.3)**
    - **CVE-2006-2369**: Обход аутентификации через security type None. Эксплуатация этого CVE позволяет получить полный доступ к системе.

### 4. Рекомендации по защите

1. **FTP (vsftpd 2.3.4)**
   - Обновите версию vsftpd до 3.0.3 или выше.

2. **SSH (OpenSSH 4.7p1)**
   - Обновите версию OpenSSH до 5.3p1 или выше.
   - Включите двустороннюю аутентификацию (public key authentication).
   - Отключите root login.

3. **Telnet**
   - Используйте SSH вместо Telnet для удаленного доступа.
   - Если Telnet используется, включите шифрование данных.

4. **SMTP (Postfix smtpd)**
   - Обновите версию Postfix до 3.8.6 или выше.
   - Настройте smtpd_data_restrictions и smtpd_discard_ehlo_keywords для защиты от SMTP smuggling.

5. **DNS (ISC BIND 9.4.2)**
   - Обновите версию BIND до 9.14.0 или выше.
   - Настройте безопасные зоны и ограничьте доступ к DNS-серверу.

6. **HTTP (Apache httpd 2.2.8)**
   - Обновите версию Apache до 2.4.54 или выше.
   - Настройте HTTP/2 для защиты от malformed requests.

7. **Samba (smbd 3.X - 4.X)**
   - Обновите версию Samba до 4.14.0 или выше.
   - Настройте безопасные настройки для Samba.

8. **MySQL (MySQL 5.0.51a)**
   - Обновите версию MySQL до 5.7.38 или выше.
   - Настройте безопасные настройки для аутентификации.

9. **PostgreSQL (PostgreSQL DB 8.3.0 - 8.3.7)**
   - Обновите версию PostgreSQL до 13.10 или выше.
   - Настройте безопасные настройки для random number generator.

10. **VNC (protocol 3.3)**
    - Используйте современные версии VNC с шифрованием данных.
    - Настройте безопасные настройки для аутентификации.

# IMPACT — Что злоумышленник мог бы сделать

Получив root-доступ и взломав учётные данные, злоумышленник мог бы:

1. **Войти по SSH как `msfadmin`** → полный интерактивный доступ к серверу
2. **Подключиться к MySQL как `root`** → чтение/изменение всей БД
3. **Использовать `sudo`** → выполнение любых команд
4. **Установить persistence** → сохранить доступ после перезагрузки
5. **Развернуть backdoor** → использовать как точку входа в сеть
6. **Украсть данные** → скопировать все конфиги, БД, ключи
7. **Pivot вглубь сети** → атаковать другие машины через эту

**Что нужно защитить:**
- Сменить все дефолтные пароли (msfadmin, root, service, user)
- Обновить vsftpd до 3.0.x (устраняет backdoor)
- Закрыть порт 6200 (backdoor shell)
- Заменить Telnet на SSH
- Настроить firewall
